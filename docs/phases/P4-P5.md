# P4 + P5 — the exterior, the threshold, and the room in daylight

Two phases run as one build because they share a materials module and the lighting rig, and
splitting those would mean writing them twice.

## Goal

P4: Weld reads as the actual building — its own 59-point ring, the two tower slivers as separate
masses, a gabled roof rather than a cone, window bays that agree with the interior openings, free
orbit at stage 3, and a threshold you would show someone.

P5: the suite in daylight — plaster, oak, glazing, crimson; real 1.5 ft masonry on exterior faces
and 0.5 ft partitions with reveals at openings; sun driven by `solar.ts`; procedural furniture
instanced per type; a ceiling at 10 ft 9 in that hides in the roof-off cutaway.

## Non-goals

No interaction (P6), no first person (P7), no axe-core pass (P8). No hand-authored geometry: every
dimension comes from `src/geo/*` or `src/data/*`. No new npm dependencies.

## Why this decomposition

The build splits into modules that own disjoint files. Agents work in one tree; the ownership table
below is the whole conflict-avoidance mechanism, so it is binding rather than advisory.

| Owner | Writes | Must not touch |
|---|---|---|
| A1 materials | `src/scene/materials.ts`, `tests/materials.test.ts` | anything else |
| A2 weld geometry | `src/scene/weldGeometry.ts`, `tests/weldGeometry.test.ts` | `geometry.ts` |
| A3 furniture | `src/geo/furniture.ts`, `tests/furniture.test.ts` | any `src/scene/*` |
| A4 camera | `src/scene/orbit.ts`, `tests/orbit.test.ts` | `stages.ts`, `CameraRig.tsx` |
| B1 exterior | `src/scene/WeldExterior.tsx`, `src/scene/Threshold.tsx` | `Suite.tsx` |
| B2 interior | `src/scene/Suite.tsx`, `src/scene/Furniture.tsx` | `WeldExterior.tsx` |
| C integrate | `Experience.tsx`, `stages.ts`, `CameraRig.tsx`, `Lighting.tsx` | any A/B file |
| D1 e2e ext | `tests/e2e/exterior.spec.ts` | any source file |
| D2 e2e int | `tests/e2e/interior.spec.ts` | any source file |

**Neither of those two files was ever created, and the coverage went elsewhere instead.**
Recorded rather than quietly dropped, because a plan naming a gate that does not exist reads
as a gate that does. The exterior is covered by `campus.spec.ts`, whose stage loop gates draw
calls and geometry count at stages 1–3, and by `threshold.spec.ts`, which drives the shell
through all four cutaway modes at stages 3 and 4 and measures triangles per mode; the geometry
itself has 42 unit tests in `tests/weldGeometry.test.ts`. The interior is covered by
`edit.spec.ts` and `journey.spec.ts`. So the rows above are stale ownership, not a gap — but
the two filenames should not be resurrected on the strength of this table alone.

A-tier files do not exist yet, so A1–A4 cannot collide. B-tier consumes A-tier by import only.
C is the only writer of the three shared files.

## Interface contracts

These signatures are fixed. A downstream owner that finds one inadequate says so rather than
changing it, because two owners changing one signature is the failure this table exists to prevent.

### `src/scene/materials.ts` (A1)

```ts
export const SCAN = { void: "#06203F", voidDeep: "#041426", grid: "#0C3260",
                      line: "#8FC4F2", lineHi: "#FFFFFF", mark: "#E4526F" } as const;
export const DAY  = { sky: "#D9E2EC", plaster: "#F0EDE7", plasterSh: "#DFDAD1",
                      oak: "#B5813F", oakDeep: "#A5732F", crimson: "#A41034",
                      glass: "#CFE4F2", edge: "#8C8578" } as const;

/** Procedural oak grain as a normal map. No texture files: CanvasTexture at build time. */
export function oakNormalMap(size?: number): THREE.Texture;
/** Cached singletons -- a new material per frame is the classic R3F leak. */
export function materials(): {
  plaster: THREE.MeshStandardMaterial;
  oak: THREE.MeshStandardMaterial;
  masonry: THREE.MeshStandardMaterial;
  glazing: THREE.MeshPhysicalMaterial;
  crimson: THREE.MeshStandardMaterial;
  oakDeep: THREE.MeshStandardMaterial;
  slate: THREE.MeshStandardMaterial;
  brick: THREE.MeshStandardMaterial;
};
export function disposeMaterials(): void;
```

`materials()` must be idempotent — calling it twice returns the same objects. Assert that.

### `src/scene/weldGeometry.ts` (A2)

```ts
export type WeldMasses = {
  walls: THREE.BufferGeometry;   // the 59-point ring extruded to eaves (60 ft)
  roof: THREE.BufferGeometry;    // gabled, ridge along the 13.2 deg long axis, 85.4 ft
  towers: THREE.BufferGeometry;  // the ring's two narrow slivers, carried above the eaves
  bays: THREE.BufferGeometry;    // window reveals, one box per opening of kind "window"
};
export function buildWeld(params?: SuiteParams): WeldMasses;
/** Window rects in the building frame, derived from walls.ts openings. */
export function bayRects(params?: SuiteParams): { u: number; v: number; w: number; h: number }[];
```

The roof is **gabled, not hipped**: a ridge line parallel to the long axis, two sloping planes, and
a vertical triangular gable wall at each end. `roofGeometry()` in `geometry.ts` fans to a single
apex, which is a cone with n sides; that is what this replaces. The ridge must run along the
13.2° axis — get it from `weld.json` `long_axis_deg_e_of_n`, never by eyeballing the ring.

Tower slivers: find them in the ring rather than hard-coding indices. They are the ring lobes whose
width is under ~14 ft; `weld.json` documents the wings. If the ring does not clearly yield two,
emit an empty geometry and say so in the return — do not invent them.

### `src/geo/furniture.ts` (A3)

Pure. Imports `@/geo/rooms` and `@/geo/collide` only. **No three.js import** — this is the same
rule that keeps `rooms.ts` testable in Node.

```ts
export type FurnitureKind = "bed" | "desk" | "chair" | "dresser" | "sofa" | "table" | "shelf";
export type Piece = { id: string; kind: FurnitureKind; room: string;
                      u: number; v: number; du: number; dv: number; h: number; yaw: 0|90|180|270 };
/** Harvard-issue dimensions in feet. Mattress is 38 x 80 in = 3.167 x 6.667 ft. */
export const SIZES: Record<FurnitureKind, { du: number; dv: number; h: number }>;
/** Default fit-out for a suite: four beds, four desks, seating in the common room, K as a study. */
export function layout(suite: Suite, opts?: { beds?: number }): Piece[];
```

Every piece must satisfy `placeIsLegal` from `collide.ts` against its room and the other pieces.
Assert that over the default params **and** over randomized params, because the whole point of a
parametric suite is that sliders move the walls.

Beds need 2 ft of clearance on one long side and the bedroom is 10 x 16, so two beds per bedroom is
the only arrangement that fits; check it rather than assuming it.

### `src/scene/orbit.ts` (A4)

```ts
export type OrbitClamp = { minRadius: number; maxRadius: number;
                           minPolarDeg: number; maxPolarDeg: number };
export const STAGE3_CLAMP: OrbitClamp;
/** Spherical orbit state -> a keyframe, clamped. Pure, no three.js. */
export function orbitKeyframe(base: Keyframe, o: { azimuthDeg: number; polarDeg: number;
  radius: number }, clamp?: OrbitClamp): Keyframe;
export function clampOrbit(o: {...}, clamp: OrbitClamp): {...};
```

`maxPolarDeg` must stop the camera before it goes under grade — below the horizon a building with
no underside reads as a hole. `minRadius` must stay outside the 143 ft footprint.

### `src/scene/Threshold.tsx` (B1)

A scanline sweep across the gable as the shell dissolves. Implement with a `clippingPlanes` /
`onBeforeCompile` band or an alpha ramp driven by world Y — no new dependency. Props:
`{ progress: number; axis: "v" }`. Under `prefers-reduced-motion` the sweep does not animate: the
shell hard-cuts at progress 0.5. `useStore(s => s.reducedMotion)` already carries that.

### `src/scene/Lighting.tsx` (C)

Sun direction from `sunPosition()` in `solar.ts` for a date/time in the store, hemisphere fill from
`--sky`, one shadow-casting directional light at 2048 (1024 on mobile), soft shadows. The P2
hemisphere hack in `Experience.tsx` moves here and gets real values.

## Build order

1. A1–A4 in parallel. Each ships with its own unit tests and must pass `npx tsc --noEmit`.
2. B1, B2 in parallel, consuming A by import.
3. C integrates: lighting, store fields (`date`, `hour`, `orbit`, `cutaway`), wiring, one green
   `tsc` + `npm test` + `npm run build`.
4. D1, D2 write the e2e gates in parallel.
5. Adversarial pass: every new assertion gets mutated and must be seen to fail.

## Verification

| Gate | How |
|---|---|
| Roof is gabled, not conical | Unit test: the set of distinct vertex heights at the ridge is a **line**, not a point — at least two ridge vertices, both at 85.4 |
| Ridge follows the long axis | Unit test: the ridge segment's bearing is within 1° of 13.2° |
| Bays agree with the interior | Unit test: every `bayRects()` entry maps through `place.ts` to a point inside Weld's real ring per `collide.ts` |
| Furniture is legal | Property test over 200 randomized param sets |
| Materials are singletons | `materials() === materials()` |
| Threshold reads at 0, 0.5, 1 | Screenshots plus the existing coverage + colour-tone gates |
| Reduced motion jump-cuts | Playwright with `reducedMotion: "reduce"`: no intermediate camera position between stage 4 and 5 |
| North rooms get no direct sun | `interior.spec.ts` at 08:00 and 13:00 on 2026-09-15 and 2026-12-21 |
| Draw calls | Exterior ≤ 8 + composer, suite ≤ 25 + composer, gated on `window.__perf` |

Frame time is recorded, never gated: headless Chromium is SwiftShader, where bloom costs ~70 ms
against 1–3 ms on a real GPU.

**The 25 was widened to 40 when shadows were switched on**, and the figures are worth keeping
because they are the measurement rather than the target. Stage 5 draws 27 calls with no caster at
all, 35 with the furniture casting, and 38 with the walls and ceiling casting too. A shadow pass
costs one call per caster batch and the fit-out is eight of them. Furniture-only ships, because
contact shadow under a bed is what stops furniture reading as floating while wall-on-wall shadow
inside one lit room is nearly invisible. `Lighting.tsx` carries the full account;
`tests/e2e/edit.spec.ts` gates it structurally through `__perf.shadows` and `__perf.casters`,
because a shadow and a dark oak board are the same pixels and no pixel test can tell them apart.
`campus.spec.ts`'s ≤ 30 for stages 1–3 is unchanged: nothing casts there.

**The exterior's "≤ 8" was never a draw-call budget, and no gate asserts it.** It is a budget of
*meshes* — walls, roof, towers, bays, plus the sweep while the threshold runs — and it got
written into the table above as calls. `WeldExterior.tsx`'s own header made the same slip and was
corrected in `8d2e70b` from a measurement: an opaque mesh costs one draw call, a transparent
`DoubleSide` mesh costs two, because three submits it twice. So those five meshes are 10 calls at
the stage-4 mid-crossing, 27 with the composer, against `campus.spec.ts`'s 30 — under budget, and
never in danger of eight. Measured across the four cutaway modes at stage 3: none 26 calls /
16,899 triangles, roofOff 24 / 16,709, wallsDown 24 / 16,691, section 23 / 16,595, reproduced
independently by three separate passes. The honest statement is that the exterior is gated at 30
alongside the campus, and the 8 is a mesh count worth keeping as one.

## Risks

| Risk | Mitigation |
|---|---|
| The gable roof is wrong on a 59-point ring with wings | Build it from the axis-aligned building frame, then transform, rather than from the ring directly. Fall back to a ridge over the main mass with hips over the wings. |
| An agent changes a shared file anyway | C is the only writer of the three shared files; `git diff --stat` after each tier catches it. |
| Procedural oak grain looks like noise | Grain runs along one axis with low-frequency banding, not isotropic noise. Judge it in a screenshot, not in code. |
| Furniture makes the suite unreadable at stage 5 | The stage-5 shot is diagonal from a corner; check it still shows floor and two walls. |
