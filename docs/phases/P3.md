# P3 — The campus in cyanotype

Turn the grey-boxed campus into the look selected in the direction review: white
line work on Prussian blue, the process an 1872 architect would have used to draw
Weld. Palette from `design-system/MASTER.md`.

**Done when:** stages 1–3 match the direction-A panel, draw calls are reported and
lower than P2's baseline, frame time is measured, and Weld is distinguished by
more than hue.

---

## Scrutiny before writing

### 1. Line width is an accessibility requirement, not a style choice

WebGL caps `gl.lineWidth` at 1px on every major platform — the value is silently
ignored. `MASTER.md` requires **≥1.5px at 1× DPR, scaled by `devicePixelRatio`**,
because the style DB rates thin-line-on-dark as poor for accessibility and this
whole look is thin lines on dark.

So edges cannot be `LineBasicMaterial`. They need `LineSegments2` +
`LineMaterial` (three's `examples/jsm/lines`, re-exported by drei as `<Line>`),
which draws lines as camera-facing quads and honours width in pixels.
`LineMaterial` also needs `resolution` kept in sync with the canvas or the width
is wrong.

### 2. Merging, and what it is actually worth

P2's baseline is **36 separate building meshes = 36 draw calls**. Merging the
masses into one `BufferGeometry` via `three-stdlib`'s `mergeGeometries` takes that
to 1. Edges merge into a second. So stages 1–2 should land at roughly 4 draw calls
including the grid, against 36.

Merging costs the ability to address a single building — which matters, because
Weld has to be highlighted. So Weld is deliberately **excluded from the merge** and
drawn separately. One extra draw call, in exchange for being able to style it.

### 3. Weld cannot be marked by hue alone

`MASTER.md`: colour is never the only indicator. Three signals together —
- white edges at 2.2px against the campus's `#8FC4F2` at 1.5px,
- a slow opacity pulse on its mass,
- a DOM label chip anchored to it via drei's `<Html>`, on `--chip-scan` so the
  text sits on a solid ground rather than on the gradient.

The pulse must respect `prefers-reduced-motion`; under reduced motion it holds at
its brightest rather than animating.

### 4. Bloom: one pass, and it needs a dependency

`@react-three/postprocessing@3.0.4` declares `react ^19`, `three >=0.156`,
`@react-three/fiber ^9` — compatible with what is pinned. Installing it for a
single low-strength `Bloom`. Nothing else post: no DOF, no vignette pass (the
vignette is a cheap radial gradient in the DOM, which costs no frame time).

Risk: bloom on a scene that is mostly thin bright lines can wash out. Threshold
kept high (`luminanceThreshold` 0.75) so only the white Weld edges bloom, not the
whole campus.

### 5. Measuring, not asserting

`renderer.info.render.calls` and `.triangles` get exposed on `window` in
development so Playwright can read them. The perf test records numbers rather than
merely passing, because "draw calls went up 10×" is the kind of regression that
silently ships.

## Verification

1. `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run test:e2e`.
2. Draw calls at stages 1–3 reported and below P2's 36.
3. Frame time over 60 frames, reported.
4. A pixel test that Weld's edges are brighter than a neighbour's — the
   highlight's whole point, and the kind of thing that silently breaks.
5. Break every new assertion and confirm it fails.

## Not in this phase

No interior work, no sun, no orbit constraints, no first-person, no mobile path.
The interior keeps P2's flat materials until P5.
