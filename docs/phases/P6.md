# P6 — make it changeable

The phase that answers the user's original ask: *"a draggable, changeable thing."* Everything
before this is a film; this is where it becomes a model of a room you can be wrong about and fix.

## Goal

Rearrange the suite, correct any dimension the project inferred rather than sourced, and send
someone a link that reopens exactly what you were looking at.

## Non-goals

No first person (P7). No axe-core sweep (P8). No new geometry — P6 only moves and re-measures what
P4/P5 already built.

## Why this is the phase the layout risk is spent on

`docs/DIMENSION-AUDIT.md` tags every number GIVEN, DERIVED or INFERRED. The INFERRED ones are the
project's exposure: ceiling height appears in no public source, the bathroom's depth was bounded
rather than sourced, and which end of the building the suite sits at is unknowable from outside.
The mitigation was decided early and this phase delivers it: **every inferred value ships as a
control**. Being wrong then costs a drag, not a rebuild.

That is also the test of the parametric core. `buildSuite()` is a pure function and `buildWalls()`
derives the walls as the room complement, so a slider is not a special case — it is the ordinary
path exercised with a different argument. If a slider breaks the walls, the core was never
parametric.

## Interface contracts

### `src/state/url.ts` (F1)

```ts
export type Snapshot = {
  stage: StageId; params: SuiteParams; pieces: Piece[];
  facade: "east" | "west"; mirrored: boolean; kUse: "study" | "bed" | "store";
  beds: Record<string, 1 | 2 | 3>; cutaway: CutawayMode; hour: number; day: string;
};
export function encode(s: Snapshot): string;   // one compact query param
export function decode(q: string): Snapshot | null;   // null on anything malformed
export const DEFAULT_SNAPSHOT: Snapshot;
```

Round-trip is the whole contract: `decode(encode(s))` deep-equals `s` for every `s`, property-tested
over randomized snapshots. `decode` must be total — a truncated, reordered, or hostile string
returns `null` and the app opens at defaults rather than throwing. A URL is untrusted input.

Do not use `JSON.stringify` straight into the query: it is long enough to hit shell and messaging
truncation, which is exactly the case the feature exists for. Encode positions on the 0.5 ft grid
`collide.ts` already snaps to, so a position costs a small integer rather than a float.

Guard `-0`. `frames.ts` has a `negate()` helper specifically because `-0` leaks into serialized
state and breaks round-trip equality while looking identical in a log.

### `src/geo/drag.ts` (F2)

Pure. Imports `@/geo/rooms`, `@/geo/collide`, `@/geo/furniture`. **No three.js.**

```ts
export type DragResult =
  | { ok: true; piece: Piece; snapped: "grid" | "wall" | "none" }
  | { ok: false; reason: "collision" | "outside-room" | "blocks-door"; against: string[] };
export function tryMove(piece: Piece, to: { u: number; v: number }, ctx: {
  suite: Suite; pieces: Piece[]; openings: Opening[];
}): DragResult;
export function tryRotate(piece: Piece, ctx: ...): DragResult;
/** Keyboard equivalent: one grid step, or one 90 deg turn. */
export function nudge(piece: Piece, dir: "u+" | "u-" | "v+" | "v-", ctx: ...): DragResult;
```

`blocks-door` is not optional politeness. `unreachableRooms()` in `rooms.ts` exists because a suite
whose rooms cannot be entered is the failure this geometry can silently produce; a dresser parked
across the only door is the same failure at furniture scale. Reject it, and name what it blocks.

`snapToWalls` and `snapToGrid` already exist in `collide.ts` with `GRID = 0.5` and
`WALL_SNAP = 1`. Use them; do not write a second snapping rule.

### `src/scene/cutaway.ts` (F3)

```ts
export type CutawayMode = "none" | "roofOff" | "wallsDown" | "section";
/** Which walls to hide, given the mode and where the camera is. */
export function hiddenWalls(walls: Wall[], mode: CutawayMode, camera: Vec3,
  params: SuiteParams): Set<string>;
```

`autoFade` is the interesting one: a wall between the camera and the room it is looking into gets
dropped. Decide it by the sign of the wall normal against the camera vector — the same handedness
question that made the P2 wireframe mirror against the masses, so pin it with a test that puts the
camera on each of the four sides in turn and asserts the near wall, and only the near wall, drops.

Hysteresis matters. A wall that fades in and out as the camera crosses the exact plane flickers;
hold a dropped wall dropped until the camera is a couple of feet past the plane.

### `src/ui/Provenance.tsx` (G1)

Each slider carries a chip: GIVEN, DERIVED or INFERRED, sourced from `docs/DIMENSION-AUDIT.md`. This
is the honesty mechanism, and it is the reason the audit exists — a viewer must be able to tell
which numbers came from the housing office, which the geometry forced, and which are the project's
own guess.

Colour is never the only signal: the chip carries its word. Contrast at least 4.5:1 on both the
scan and daylight grounds, both of which the panel appears over.

## Controls, and what each is for

| Control | Range | Why it exists |
|---|---|---|
| Placement | north gable / east facade / west facade | Unknowable from public sources. The default is derived, not known. |
| Mirror | on / off | A section's suites mirror about the stair core; which hand Weld 15 is, is unknown. |
| Ceiling height | 9–12 ft | INFERRED at 10 ft 9 in, in no public source at all. |
| Bathroom depth | 6–8 ft | Bounded by the 44 ft chain, never sourced. |
| Beds per bedroom | 1–3 | Weld is documented as housing quints and sextuplets; four is the letter's number, not the building's limit. |
| K use | study / bedroom / storage | What K actually is, is unknown until September. |
| Time of day | 0–24 | Already in P5; the panel exposes it. |
| Cutaway | 4 modes | Reading a plan from outside. |

Changing a dimension must re-validate the furniture: a slider that shrinks a bedroom under its beds
either drops pieces or refuses, and says which. Silently overlapping furniture is the failure.

## Verification

`tests/e2e/edit.spec.ts`:

1. Drag a bed, read the URL, reload that URL, assert the bed is where it was left.
2. Do the same drag with arrow keys only, from keyboard focus, and get the same result.
3. Drag a bed into a wall and assert the rejection is visible — the piece returns and the reason is
   announced, not silently swallowed.
4. Drag a dresser across the bathroom door and assert `blocks-door`.
5. Drive the ceiling slider and assert the rendered wall height changes; drive the bathroom-depth
   slider and assert the wall count and the area readout both change.
6. Each cutaway mode changes the frame measurably, and `wallsDown` shows more floor than `none`.
7. A malformed URL opens at defaults with no console error.

Property tests: `decode(encode(s)) === s` over randomized snapshots; `tryMove` never returns
`ok: true` for a placement `placeIsLegal` rejects, over randomized suites and pieces.

Every assertion gets mutated and seen to fail. Restore from an explicit `.bak` copy, never from
`git checkout` — several of these files are new and untracked, where `git checkout` is a silent
no-op that leaves the mutation live.

## Risks

| Risk | Mitigation |
|---|---|
| URL grows past what a message client will carry | Grid-quantised integers, not JSON. Measure the encoded length in a test and bound it. |
| Drag on a rotated suite feels wrong | The suite sits on a 13.2° axis. Convert the pointer ray into the suite frame through `place.ts`, never approximate with screen deltas. |
| A slider produces an illegal suite | `findOverlaps` and `unreachableRooms` already exist and run on every param change; the panel refuses and explains rather than rendering a broken suite. |
| Keyboard path is an afterthought | It is `nudge()`, the same function the pointer path calls. One code path, two inputs. |
