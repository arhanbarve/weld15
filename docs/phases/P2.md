# P2 — Grey-box vertical slice, all six stages

Build the whole journey ugly but complete, so the one genuinely risky part — the
through-the-wall threshold — gets judged before anything is polished. No
materials, no lighting design, no post-processing. Untextured boxes.

**Done when:** Playwright drives the stage scrubber 0 → 5, every stage renders lit
geometry, no console errors, the skip control is first in tab order, and the
reduced-motion path jump-cuts instead of flying.

---

## Scrutiny before writing

### 1. Scale and precision

One world unit = one foot, origin at Weld's centroid, matching `frames.ts`. The
camera runs from ~4,000 ft out at Cambridge down to ~2 ft inside a bedroom. That
is a 2,000:1 range, well inside float32 — depth precision only bites past about
1e5:1. Camera near 0.5, far 25,000.

The exception is the globe. Earth at foot scale is 2.1e7 ft in radius, which
would wreck depth precision and needs its own scene graph at unit scale, cut to
stage 1 rather than flown. So stage 0 → 1 is the one hard cut in the sequence;
1 → 5 is continuous.

### 2. What "grey-box" means here, precisely

Geometry from the real data, materials deliberately flat:

| Stage | Content | Source |
|---|---|---|
| 0 Orbit | unit sphere, marker at Boston | hand-made |
| 1 Cambridge | 36 building masses | `campus.json` + `extrude.ts` |
| 2 Yard | same geometry, Weld highlighted | same |
| 3 Weld | Weld's 59-point ring, 60 ft mass + roof to 85.4 | `weld.json` + `extrude.ts` |
| 4 Threshold | gable dissolving, interior fading up | both |
| 5 Suite | floors, wall bands, openings | `buildSuite` + `buildWalls` + `place.ts` |

Weld is a 60 ft mass with a pitched roof to 85.4 ft, not an 87 ft box. Cambridge
GIS gives eaves 60 and ridge 85.4, and 5 floors × 12 ft = 60 exactly.

### 3. The threshold, which is the whole point of this phase

Approach: one scalar `t` in 0..1 across stage 4. The camera moves along a spline
from outside the gable to inside bedroom B. The exterior's opacity goes 1 → 0 over
`t` in 0.2..0.7; the interior's goes 0 → 1 over 0.4..0.9. They overlap, so there
is never a frame showing neither.

Rejected alternatives, recorded so they are not re-litigated:
- **A clipping plane on the gable.** Cleaner in principle, but `three` clipping
  planes are per-material and would need every campus material to carry them.
- **Camera-relative stencil.** Better looking, much more code, and P2 exists to
  find out whether the move works at all.

Fallback if the dissolve reads badly: a hard cut behind a scanline wipe, which is
a change confined to `Threshold.tsx`.

### 4. Draw calls: deliberately not optimised

36 separate building meshes at stage 1–2. Merging into one `BufferGeometry` is
P3's job. Recording the number now so P3 has a baseline to beat.

### 5. Reduced motion is a branch, not a duration

`prefers-reduced-motion: reduce` must not merely shorten the fly — it must not fly
at all. The camera snaps to each stage's keyframe. Tested by asserting the camera
reaches its target within one frame.

## Verification

1. `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run test:e2e`.
2. `journey.spec.ts` sets each stage, waits for the camera to settle, and asserts
   the frame contains lit geometry using the measured-luminance method from
   `scripts/measure-render.mjs` — the same gate that caught two vacuous render
   tests in P0.
3. Screenshot each stage into `design/renders/p2-stage-N.png` for review.
4. Break each new assertion and confirm it fails.

## Not in this phase

No materials or palette work, no sun, no furniture, no orbit constraints, no
cutaway, no first-person, no URL state, no mobile path. Each is a later phase.
